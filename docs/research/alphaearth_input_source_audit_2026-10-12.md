# AlphaEarth 来源与项目输入设计审阅

日期：2026-10-12

来源审阅结论：先从地铁干预响应任务定义候选信息，再核对 AlphaEarth 的来源、潜在重叠与实际增量，不能仅凭通用嵌入的来源清单认定它覆盖全部商业、活力或道路信息。

后续用户确定的下一轮分工：完整 AlphaEarth 作为背景，与房价、人口及城市统计量共同编码；POI、基线 VIIRS、街景和独立卫星图像作为状态；本轮不输入路网。当前正式设计见 [输入契约](state_context_input_contract_2026-10-12.md)。以下来源事实仍适用，其他输入路线保留为比较方案，不代表新架构已经完成实现或已证明信息互补。

本审阅核对原论文最新版 arXiv v2 的 Table S1、S15 与 S22.3，以及 Google 的产品说明。论文版本号与模型/数据产品版本号是不同概念。Google 产品说明对应 AEF v2.1；当前缓存的具体模型和数据版本仍应从采集元数据核对，不能仅依据当前网页反推。

## 公开来源的实际分工

| 分工 | 数据 |
|---|---|
| 生成嵌入的直接输入，同时用于训练目标 | Sentinel-2 光学、Landsat 8/9 光学与热红外、Sentinel-1 雷达 |
| 训练目标 | PALSAR-2、Copernicus DEM、GEDI、ERA5-Land、GRACE、NLCD、Wikipedia 与 GBIF 文本 |
| v2.1 的补充训练目标 | USDA Cropland Data Layer |

Table S1 列出的来源不包括高德商业 POI 面板、VIIRS 夜间灯光和 OSM 路网。Wikipedia 包含部分地标等地理文本监督；它的覆盖、属性与商业 POI 面板不同。公开来源未直接使用某类数据，不代表嵌入中完全不存在相关信息：商业、活力、道路等可能通过相关地表形态产生代理信号，此处属于推断，需要本项目验证。

来源：[原论文 Table S1、S15 与 v2.1 说明 S22.3](https://arxiv.org/html/2507.22291v2)、[Google 产品说明](https://developers.google.com/earth-engine/datasets/catalog/GOOGLE_SATELLITE_EMBEDDING_V1_ANNUAL)。

## 如何理解信息重叠

需要区分三件事：来源直接重复、表达的内容可能重叠，以及在现有输入之上的预测增量。这三项不能用“AlphaEarth 包含一切”或“来源不同所以完全互补”替代。

例如，Sentinel-2 NDVI/NDBI 与 AlphaEarth 有明确的传感器来源重叠；显式指标仍可能提供可解释信息。POI 与夜光虽然没有列在 AlphaEarth 的公开来源中，商业密度和活力仍可能与遥感形态相关。仅凭来源清单不能确定实际冗余。

## 项目候选输入

以下是基于任务的设计建议，并非已经验证的性能结论。

| 候选信息 | 在本任务中的作用 | 当前处理建议 |
|---|---|---|
| 街景 | 街道界面、商业招牌、步行环境等地面信息 | 状态候选核心模态，核对有效历史覆盖 |
| POI 结构与历史变化 | 商业类别、组合与动态 | 保留独立候选，不因 AlphaEarth 可能包含代理信息而自动删除 |
| 基线 VIIRS 与历史趋势 | 干预前活力及其变化 | 保留独立候选；与后期准实验响应分清角色 |
| 路网拓扑、中心性、步行可达性 | 既有连接结构及干预作用机制 | 用户确定本轮不输入；不新增采集作为本轮前置任务 |
| 可解释物理环境指标 | 植被、建成强度、地形等 | 与 AlphaEarth 对比，判断是否需要同时使用 |
| 房价、人口和城市汇总量 | 局地与城市社会经济背景 | 背景候选，按既有干预前 lag 路径构造并附缺失标记 |
| AlphaEarth | 综合遥感环境表征 | 按后续约定进入背景；与独立卫星图像等的实际增量通过比较评价 |
| 独立卫星图像 | 本任务自行编码的地表空间形态 | 按后续约定进入状态；需独立影像资产，不能复制 AlphaEarth 向量代替 |

路网之前放入状态，是因为道路连接结构属于建成环境，可能影响政策响应，并非模型接口要求。若研究更关注街景与商业活动状态，可将既有路网指标归为结构背景。地铁开通带来的可达性变化则应与既有路网分开，作为干预描述候选。

项目数据清单记录的 OSM 路网为 2026 截面，且未启用。不能将它直接宣称为 2010–2024 年事件的干预前路网。当前主方案先不默认使用它；历史来源核对或明确回顾性敏感性分析可以并行推进。依据：`docs/data/data_inventory.md:44` 与 `:65`。

## 两条可比较的输入路线

1. **显式输入路线**：先选择任务相关的街景、商业结构、基线活力、社会经济背景，以及少量可解释物理环境指标，建立不依赖 AlphaEarth 的模型。
2. **AlphaEarth 路线**：在相同协议中加入完整嵌入及可学习投影，或用它替代显式物理环境特征，观察是否带来额外收益。状态融合与背景条件化也是可比较的组织方式。

参考 AlphaEarth 的来源用于设计本项目原始输入，不意味着要复制其全部传感器、训练目标或预训练模型。也不能从缓存的 64 个潜在坐标中直接剥离出“POI 部分”或“夜光部分”。如果希望严格限定遥感编码器的信息来源，应使用明确的原始数据重新构造对应特征或编码器。

## 最小验证顺序

- 在训练城市中，用简单探针测试 AlphaEarth 对已有基线 POI、VIIRS、NDVI/NDBI 等的可预测性；这衡量潜在重叠，不能替代任务增量评价。
- 在验证城市中，比较显式输入模型、加入 AlphaEarth 的模型，以及用 AlphaEarth 替代显式物理环境指标的模型。固定事件支持集、监督 mask 和信息截止日期。
- 对 POI 与基线夜光分别做增量/移除比较，决定哪些输入值得同时使用。
- 按用户约定的状态 `S_i`、干预 `T_i`、背景 `C_i` 分工细化正式字段与模型接口，并用上述比较评价实际增量。测试城市仅用于最终评价。

上述验证尚未运行；本地缺少完整生产 model_inputs 和真实街景资产，本次更新只完成来源审阅和设计修正。
